Polling control

Within one type — PM or CM — exactly one election can be open at a time. Opening one closes the other of the same type, which is what lets a terminal determine the right ballot without being configured per booth. PM and CM are independent of each other.

Start the next election

Creates a new election for the type and opens it, closing whichever one of that type was open before. PM and CM each count up from their own most recent cycle.

CM polling by state

A CM election is not one national event — each state runs its own. A freshly-started CM election opens with every state closed; open each state here when that state's polling is ready to begin.

Terminal activity

Live votes recorded per terminal for whichever election is currently open — a booth that has gone quiet shows up here immediately. Terminal registration and provisioning live on the Terminals page; this is live monitoring only.

No election is currently open.

There is no reset or clear option. Recorded votes are immutable in the database, so re-running a demonstration means restoring a database snapshot.

Voting terminals

Each terminal has its own credentials, so one can be revoked without disturbing the others. A provisioning secret is displayed once and never again.

Ledger audit

Every recorded vote is committed to a hash chain persisted in the database. Verification recomputes the whole chain, so any alteration to a stored ballot is detectable. Entries are anonymous: the ledger proves nothing was changed without revealing who voted for whom.

Voter registration

Voter ID and NFC card ID are assigned automatically on registration — the two are always the same value, so there is nothing to type here. The assigned ID appears below once the voter is registered.
A voter must be at least 18 years old on the day of registration — the minimum voting age under Article 326 of the Constitution. Registration is blocked below that age.

Biometric enrollment

A fingerprint template is enrolled automatically when this voter is registered — no separate capture step is needed here. Until the MFS100 scanner is connected, this uses the hardware simulation: registration returns a fingerprint code tied to this voter, which the simulated scanner accepts in place of a real fingerprint.
